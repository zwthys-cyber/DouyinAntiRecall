# DouyinAntiRecall · 抖音增强

适配 **抖音 41.2.0（412021）/ iOS 17.0 + TrollStore**，通过 TrollFools 注入独立 `DouyinAntiRecall.dylib`。插件不依赖 Substrate、Theos 或额外动态库。

v0.2.8 在原有消息防撤回和灰色“已撤回”标签上，加入抖音设置入口、IP 属地、音频库/评论区发送音频、图文原图保存。新版补齐评论图片原图下载、手动评论时长和其他拍摄日期元数据。新增功能的真实抖音界面和发送/相册结果需要设备验收；云端使用与静态接口对应的模拟对象测试。

## 安装与设置

从 [Releases](https://github.com/zwthys-cyber/DouyinAntiRecall/releases) 下载最新版。退出抖音，用 TrollFools 移除旧 dylib，再注入新版，重新打开抖音。已有缓存可以保留。

进入 **抖音 → 设置 → 抖音增强**。各项均有独立开关：

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 消息防撤回 | 开 | 保留本机收到的他人消息 |
| 显示已撤回标记 | 开 | 气泡旁的小号灰色标签，支持即时刷新 |
| 显示 IP 属地 | 关 | 视频时间旁显示平台提供的属地或省市 |
| 视频音频入库 | 关 | 长按视频将音乐保存到音频库 |
| 评论区发送库内音频 | 关 | 选择文件后替换下一次评论语音 |
| 评论时长跟随手动录音 | 开 | 保留手动时长字段，音频文件不裁剪 |
| 无水印保存图文 | 关 | 长按图文保存当前原图或整组图片 |
| 评论图片无水印 | 关 | 评论图片原生保存使用原图地址 |

“IP”指 IP 属地，不是网络地址。使用本机离线城市码表和平台数据，无额外位置查询账号。

## 音频和原图

新增两个独立开关：“评论时长跟随手动录音”默认开，仅改变时长字段的处理方式；“评论图片无水印”默认关，开启后评论区原生保存会改用原图地址。

音频库可以从插件设置直接打开，支持文件导入、试听、删除。开启音频入库后，视频长按菜单会出现“音频入库”和“音频库”。

在音频库点每条音频右侧的 **发送**（旁边的播放按钮可以试听），准备完成后回评论区，按你希望提交的评论时长手动录音后松开，发送已选音频。默认保留手动录音的评论时长字段，音频文件仍保持原长度，不裁剪、不再截取前 29.5 秒；两者可以不同。每次准备仅使用一次、5 分钟内有效。关闭开关、手动取消或重启会清除待发状态。此功能需要账号本来就有评论语音按钮。

开启原图开关后，长按图文可选择“保存当前原图”或“保存整组原图”。优先使用 `watermarkFreeUrlList`，需要允许添加相册。下载服务端原图，不抹除已经烙在像素中的水印；不被相册支持的格式会尝试原分辨率 JPEG 兜底。本版不包含无水印视频下载或实况视频导出。

详见 [功能说明](docs/FEATURES.zh-CN.md)、[安装说明](docs/INSTALL.zh-CN.md) 和 [验收步骤](docs/VALIDATION.zh-CN.md)。

## 消息保留和数据

原文保持不变，撤回状态作为独立的 10 号灰色标签。优先放气泡下方，空间紧时靠右下侧；无空位时隐藏以避免覆盖文字。按账号、会话、消息身份主动刷新，复用单元格时清理状态。自己发送或当前账号执行的撤回继续走原逻辑。

消息缓存位于 `Library/Application Support/DouyinAntiRecall/messages.json`，最多 1000 条、内容约 8 MiB、单条 64 KiB。缓存按账号/会话隔离，不上传，排除 iCloud 备份，首次解锁后可读取。关闭开关或移除插件不会删除缓存。

保存原图时读取 EXIF `DateTimeOriginal`、XMP 原始拍摄日期和 IPTC 内容创建日期，有有效拍摄日期就设置相册时间；兼容 JPEG 转换也保留该日期。缺少或无效时保留系统默认时间，不用发布时间代替。无时区的日期按设备本地时区解释。保存提示分别显示保存张数、识别日期张数和成功按日期归档张数。首个地址失败会尝试备用原图地址；下载或相册失败显示错误原因和代码。

音频库位于 `Documents/DouyinAudioLibrary/`，单个文件不超过 50 MB；音频准备文件只用于本机下一次评论发送。删除文件或停用功能会取消相关待发状态。消息/音频数据均在抖音自己的沙盒中。

不能恢复未收到的消息或服务器已经删除的媒体附件。历史保留依赖已有缓存或更新模型仍提供的原文。

## 登录诊断

v0.2.6 在应用启动后显示“诊断 v0.2.6”悬浮按钮，不依赖先触发某个错误回调；未登录也能查看，设置页亦可进入。独立窗口位于应用登录弹层上方，不接管键盘焦点，按钮外触摸穿透。报告显示插件加载版本、宿主是否匹配和观察点安装数量，也可复制最近 16 条错误域、错误码、处理路径，以及系统、宿主版本和签名中的 App ID / Team / App Attest 字段。记录仅保存在内存，重启清空，不读取错误正文、手机号、验证码、请求参数、登录令牌或响应正文。

本版用于定位重签包安装成功后仍提示“版本过低或非官方渠道”的真实错误；不代表已修复登录兼容性。签名字段只是读取结果，不是证书或服务器信任验证。

诊断版在同包标识但宿主构建号不匹配时仍显示只读入口，便于发现签名工具是否改写版本；防撤回和其他功能 hook 仍保持禁用。应用恢复前台、窗口出现时会重试诊断观察点。


## 消息通知修复

v0.2.7 增加「抖音 → 设置 → 抖音增强 → 消息通知修复」，诊断弹窗中也可进入。点击「开启权限并重新注册」：尚未授权或只有临时授权时请求横幅/声音/角标权限，已拒绝时引导系统设置；仅当签名 `aps-environment` 是有效的 `development` 或 `production` 字符串且通知权限允许时，重新调用系统 APNs 注册。支持刷新权限、提醒样式与系统远程注册状态，复制结果只包含这些状态，不含 device token 或聊天内容。

「5 秒后测试本地通知」安排一条无聊天内容的本地测试提醒，请返回手机桌面查看。这只证明本地提醒能够显示，不证明私信远程推送已经恢复。系统显示已注册也不表示抖音服务器接受该 token 或能向当前重签身份推送。插件不改签名权限、不伪造推送成功、不替换宿主通知 delegate，也不通过循环静音音频保活。此次升级处理本地权限与注册重试，真实后台私信送达仍需设备结果；不能承诺恢复官方推送。

使用 LCSign 覆盖更新插件时，保留此前成功登录的同一证书、包标识和「移除 Embedded」设置，不卸载当前应用；已在项目中有同名插件时替换该文件，避免重复注入。


v0.2.8 在通知修复中优先调用宿主 `BDUGPushService.requestDeviceToken` 及 `uploadDeviceTokenIfNeeded`，补齐只调用系统注册而未显式触发宿主按需绑定的重试链；宿主服务不匹配时退回系统注册。保留宿主的上传禁用、去重和频率限制，不强制修改缓存，不改开发/生产环境。私有接口严格限制 41.2.0 / 412021。

报告新增本次进程的 APNs 成功/失败回调计数、宿主上传开始/结果回调计数、最近阶段和失败数字码。观察原样转发参数，不读取 token 内容或上传结果字典；计数只在内存中保存。回调到达不等于服务端接受，重试后刷新状态，仍需另一账号真实发私信确认后台送达。

## v0.2.11 撤回占位内容处理

针对用户报告的 `Recall Content Hided`，识别仅含 `text` 字段且值为该完整字串的内容（忽略两端空白及大小写）。此类更新不覆盖原文缓存；撤回处理优先选用有效缓存，旧缓存只有占位内容时尝试当前模型的有效正文。首次在撤回模型中取得的正文也会缓存，供后续空更新使用。没有有效正文时保留宿主原生撤回处理，不将占位内容标为成功保留。

普通消息原样显示；不匹配句子内部的词语或带媒体等其他字段的结构。由于尚未取得设备上的实际内容结构，这个规则仅覆盖上述明确形态；恰好以该字串为全文的普通文本仍显示原样，但不作为可恢复原文缓存。不能恢复从未收到或已丢失的正文。[GitHub 编译、签名检查、消息缓存与模拟器回归全部通过](https://github.com/zwthys-cyber/DouyinAntiRecall/actions/runs/45017122251)，对应源码提交 `1c73db4`；真实占位消息仍需设备验收。


## v0.2.12 评论音频时长单位修正

静态核对 41.2.0 / 412021 的 `AWECommentAudioRecorderController.sendRecordMessageOrNot`：`0xfea1060` 读取常量 `0x2a80d500`（double `1000.0`），将录音器的秒数相乘、截断为整数后调用 `setDuration:`；`currentTime` 仍为秒。插件现代上传替换分支此前将 `floor(seconds)` 写入 `AWECommentAudioModel.duration`，现改为 `floor(seconds * 1000)`。此前模拟测试对象并非目标模型的子类，未覆盖此分支，现改用相同运行时类名和继承关系，并检查毫秒/秒的一致性。

修正仅作用于关闭「评论时长跟随手动录音」、且在现代上传器成功替换文件的路径。保留该开关的既有行为和默认值，完整音频不裁剪，不改文件格式和服务端响应。开启该开关时的手动时长仍原样保留；该修正不证明所有「参数不合法」都已解决，是否走到修正路径及实际发表评论仍需设备验收。[GitHub macOS 26 编译、签名与全部回归已通过](https://github.com/zwthys-cyber/DouyinAntiRecall/actions/runs/45189334915)，验证提交 `73a7641`（功能提交 `dd1be70`）。

将参考音频助手的管理流程接入当前 UIKit 页面：搜索、文件夹创建与分层浏览、导入到当前文件夹、文件/文件夹重命名、系统分享、多选批量删除、滑动操作、文件数量/大小汇总与异步时长显示。保留每行独立的试听/发送按钮、准备中的加载状态和取消待发送操作。文件夹显示在音频之前；删除有确认，不启用整行滑动直接删除。库根目录仍是 `Documents/DouyinAudioLibrary`，已有音频无需迁移。

## v0.2.13 长评论音频兼容发送

用户验证短音频能发表、长音频报参数不合法，这支持长度相关的判断，但不证明服务端精确上限为 29.5 秒。音频助手对已知超过 29.5 秒、或时长尚未加载完成的文件提供发送方式选择：「兼容发送（最长 29.5 秒）」或「仍使用完整音频」。兼容方式只导出发送副本的前 29.5 秒，原始文件和库内完整音频均不修改。

准备后重新读取导出文件的真实时长，兼容发送按该时长更新录音器秒数与现代上传模型毫秒数；即使全局开启手动时长，该次显式选择的兼容发送也使用文件时长。一次性待发状态消费或取消时清除此标志，完整音频流程沿用原时长开关。加入真实 32 秒 WAV 导出与替换回归，验证副本约为 29.5 秒、提交时长一致及原文件字节不变。实际发表评论仍需设备验收；云端编译和回归待确认。
