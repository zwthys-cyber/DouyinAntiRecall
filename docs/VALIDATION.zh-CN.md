# 验证范围

本仓库的编译和测试只在 GitHub Actions 的 macOS runner 运行。

云端检查：

- 编译实际插件源码为 macOS 测试进程，使用相同方法名和 ABI 的模拟消息模型。
- 测试收到消息后撤回的内容保留、独立撤回状态字段、重复更新不叠加、普通消息不标记。
- 测试原始模型不被修改、无关扩展和提及偏移保留、原方法调用次数、非文字内容维持原结构。
- 测试自己发出的消息正常撤回、当前账号执行撤回正常转发、未知账号/发送者回退。
- 测试缓存按账号和会话隔离、JSON null 持久化、重载恢复、单条大小和数量上限。
- iOS 模拟器运行真实 UIKit 标签测试：下方/侧边放置、空间不足隐藏、不遮挡、单元格复用、重新配置、视图模型读取和深色模式。
- 交叉编译 iOS arm64 dylib，检查 Mach-O 架构、链接依赖和 ad-hoc 签名。

未完成：iOS 17.0 真机加载、抖音真实消息通知链和聊天界面、后台及离线消息、媒体消息、群管理员撤回、不同账号切换。模拟测试不代表这些实机行为已经通过。

请在安装后验收：

1. 单聊收到文字并看到原文，对方撤回后原文仍显示，气泡下方或右侧出现小号灰色“已撤回”；普通消息不显示。
2. 完全退出并重新启动抖音，返回聊天确认原文和撤回提示是否仍在，重复加载不叠加。
3. 接收端退后台时对方撤回，再进入聊天检查；随后检查离线撤回。
4. 自己发送文字后撤回，另一设备应正常变为撤回提示。
5. 群聊收到文字后由发送者撤回；另测管理员撤回。
6. 图片、语音、视频分别测试，注意附件被服务器清除后无法凭 JSON 恢复。
7. 切换账号，确认没有串号；接着验证正常收发、已读和删除会话。
8. 移除 dylib 后重启抖音，确认恢复原逻辑。

排查加载问题时，在连接设备的 macOS Console 中筛选 local.douyin.antirecall。
日志只记录 hook 安装、版本不匹配或本地保留事件，不记录消息内容、账号或消息 ID。

新版额外验收：滚动聊天列表确保普通消息没有残留标签；分别检查短气泡、长气泡、深色模式、@提及和复制文字。状态标签不应进入复制或转发内容。

## v0.1.3 即时刷新回归

- 消息保留回归检查通知在原 SDK 方法完成后发出，包含账号、会话、消息 ID；普通消息不发出撤回刷新通知。
- iOS 模拟器先显示无标记的旧消息副本，随后只发送撤回事件，不调用重新布局、配置或重新进入页面，断言两套单元格立即出现标签。
- 验证相同消息 ID 在不同账号或会话不串状态，其他消息不受影响；原来的消息副本不被修改。
- 验证后续布局保留状态，复用清除即时状态，后台通知切回主线程更新 UIKit。

真机重点验收：双方保持对话页面打开，发送方撤回，接收方原文继续保留且灰色“已撤回”及时出现。分别检查单聊/群聊、连续撤回、滚动复用、前后台切换。模拟器测试不替代真实抖音同步路径的验收。

## v0.2.0 功能整合回归

新增：开关关闭时防撤回恢复原逻辑，单独关闭标签不影响消息保留；原生设置分组入口与六个独立开关；属地标签去重/还原、省市离线映射；两种视频长按面板增量注入、开关变化和避免重复；watermarkFreeUrlList 优先、HTTP(S) 链接筛选；生成无麦克风的 WAV 文件，验证导入、路径约束、M4A 转换、正确时长、旧评论回调、评论上传兜底、Swift 评论上传器的 ObjC 入口、单次消耗和取消竞态。

真机新增验收：

1. 抖音“设置”能打开“抖音增强”，退出重进后各开关保持原值。
2. 属地开关打开后滑到下一条视频，查看时间旁标签；关闭后恢复。
3. 长按视频进行音频入库，文件在音频库出现，能够试听、删除、导入。
4. 保持原生评论语音可用，选择音频后录约 1 秒发送；用另一账号确认声音和时长，随后普通语音应恢复正常。
5. 关闭评论音频开关、取消待发、取消录音和重新启动后分别确认状态符合说明。
6. 保存当前图片和整组图片，检查相册中的数量、分辨率和水印；拒绝相册权限时应给出提示。
7. 原有消息保留及灰色标签的即时刷新继续按前述步骤回归。

v0.2.0 加固检查：下载链接无扩展名时按 Content-Type 保留 MP3 等格式；旧录音延迟上传不消耗新选音频；明确取消的录音即使成功回调也不替换；相册兼容 JPEG 编码保持像素尺寸。

## v0.2.1 音频行尾按钮

新增模拟器回归：每行试听/发送按钮、窄屏文件名与按钮不重叠、试听绑定文件、列表重排后发送仍选择原文件、准备时加载状态和防重复点击、取消后立即重新发送、旧转换完成不覆盖新状态。通过行尾发送按钮准备的音频继续执行现有原生录音回调及上传测试。

真机请检查行尾按钮布局，点“发送”等待准备完成，再回评论区录约 1 秒松开；另一账号确认实际收到的音频。

## v0.2.2 图片拍摄时间

模拟器使用真实 Image I/O 写入的图片元数据测试：闰日、正负半小时时区、秒小数、无时区按设备时间解释、非法日期/时区和缺失字段；确认修改时间和数字化时间不冒充拍摄时间。原图与 JPEG 转换后的保存请求使用同一拍摄日期，原图字节保持不变；没有日期时不覆盖系统日期。Photos 请求使用记录参数的替身，不请求访问相册。

真机验收：保存带 EXIF 拍摄日期的图片，在系统相册信息中检查日期；再保存无 EXIF 日期的图片，确认使用系统默认时间。整组保存逐张核对，带时区的时间应正确转换到当前设备时区，保存完成提示的识别张数应匹配。若触发格式兼容转换，日期仍应一致。下载文件已移除日期时不能恢复真实拍摄时间。

## v0.2.3 保存 0 张回归

新增云端模拟器测试：真实文件内容无扩展名/无 MIME 的下载读取、HTTP 403、成功状态但非图片内容、临时文件缺失和断网错误码；Photos 请求携带由内容推断的格式及匹配扩展名；候选链接去重/优先级/备用地址。保存流水线注入下载和相册写入替身，验证首地址失败后恢复、原始格式被拒绝后 JPEG 重试、单次计数、部分失败继续下一张、没有地址计入失败、识别日期与相册成功独立计数，以及全失败时返回具体相册错误。

真机问题尚未定位到具体错误码：在之前保存 0 张的同一条图文复测。若仍失败，记录完整弹窗错误；若成功，检查相册真实图片、尺寸和日期。云端测试不访问抖音 CDN 或真实相册。

## v0.2.4 评论图片、手动时长与日期补读

新增模拟器回归：评论图片 downloadUrl 切换为 originUrl、关闭恢复、缺失原图不回退加水印地址；八个开关和默认手动时长。使用真实 32 秒 WAV，验证转换不再截到 29.5 秒，录音器手动 1.25 秒的时长字段不被替换成文件时长；现代评论上传器保持手动时长字段和完整文件，原始音频不被修改。原音频时长模式继续回归旧录音器更新路径。

使用真实 XMP/IPTC 图像验证带时区和秒小数的拍摄日期、JPEG 转换后保留、无效日期拒绝和通用文件创建时间不冒充拍摄日期。

真机验收：开启评论图片无水印后保存同一张评论图片检查角标；音频准备后按住录音几秒松开，检查评论显示/提交的时长字段与完整播放内容；确认声音未被截断。平台可能重算字段或限制发送，需要接收端核对。保存图文若仍未识别日期，表示下载字节中未找到可用日期，不能据此恢复真实拍摄时间。

## v0.2.5 只读登录诊断

云端模拟器新增回归：按已读取的 ObjC ABI 安装账户错误/1049/强制更新观察点，验证原始对象、原回调与返回结果只转发一次；实际错误域和数字码与路径记录分开；错误正文、手机号、验证码、令牌和请求/响应字典不进入报告；历史上限 16 条、nil 错误不产生误报。用构造的 Mach-O 签名样本验证 XML 权限读取和越界拒绝，验证错误后诊断按钮在可见窗口内。

真实设备仍需复现短信登录拒绝，并核对复制的代码和签名环境。无真实抖音账号请求参与云端测试，不将测试通过视为登录已修复。

## v0.2.6 启动诊断入口

新增模拟器回归：在没有任何登录失败回调前，启动入口即出现；按钮显示当前版本，独立窗口高于应用弹窗层，不能成为 key window，按钮外触摸穿透、按钮本身可点击。保留原来的隐私、事件容量、回调传递测试，补测实际升级弹窗方法的五个原始 UI 参数完整转发及独立路径记录。

真机首先在启动且未发起登录时查看“诊断 v0.2.6”。入口显示加载状态、宿主匹配状态与观察点数；登录问题仍需复制真实诊断后继续定位。用户已确认官方抖音卸载，不再将其当作待确认的覆盖冲突条件。
